# 5-C단계 설계 — 지니·멜론으로 찾기 · 그림 붙여 넣기 · 파일 이름 바꾸기

> 시안 `docs/images/stage5c_mockup.png` 승인 2026-10-31("오케이 진행해"). 기반: 5-A 브랜치 `stage5a` `96ab88f`
> (5-A 사용자 확인 전이라 그 위에 쌓는다). 5-B(즐겨찾기)는 이 단계 뒤.

## 1. 목표

국내 가요는 MusicBrainz에 없는 곡이 많다. 그래서 곡 정보 창에 세 가지를 더한다.
- 지니·멜론 검색을 브라우저로 열어, 사용자가 보고 직접 입력한다.
- 복사한 앨범 그림을 붙여 넣는다.
- 저장할 때 파일 이름을 `가수 - 제목.확장자`로 바꾼다(체크했을 때만).

**하지 않는 것**
- 앱이 지니·멜론에 직접 접속해 정보를 가져오는 것. 두 사이트 robots.txt가 일반 로봇에 `Disallow: /`이고, 공개 API도 없다.
- 알송 서버 사용. 이스트소프트 전용 비공개 서비스이고, 이 프로젝트의 이스트소프트 금지 원칙에 걸린다.
- 목록에 태그로 이름 보이기. 정렬은 파일 이름으로 하므로, 보이는 이름과 정렬 순서가 어긋난다.
- 트랙 번호를 이름에 붙이는 것(사용자 결정).
- 사용자가 저장해 둔 .m3u 파일 안의 경로를 고치는 것.

## 2. 브라우저로 찾기

- **줄 위치:** 경로 줄 바로 위. 회색 `브라우저로 찾기` + `[지니에서 찾기]` `[멜론에서 찾기]` + 작은 회색 글 `보고 직접 입력`. 고칠 수 있을 때만 보인다.
- **검색어:** 지금 `가수` 칸 + 빈칸 + `제목` 칸(앞뒤 빈칸 정리)이다. 둘 다 비면 파일 이름에서 짐작한 가수·제목(`guess_from_filename` → 제목은 `clean_search_title`)을 쓴다. 그래도 비면 단추가 꺼진다.
- **주소:** 검색어는 UTF-8 퍼센트 인코딩한다(빈칸 `%20`).
  - 지니 `https://www.genie.co.kr/search/searchMain?query={q}`
  - 멜론 `https://www.melon.com/search/total/index.htm?q={q}`
- **여는 방법:** `QDesktopServices.openUrl`로 기본 브라우저에서 연다. 앱이 그 사이트에 보내는 요청은 없다.

## 3. 그림 붙여 넣기 · 끌어다 놓기

- 그림 단추 아래 작은 회색 글 `끌어다 놓기 · Ctrl+V`(고칠 수 있을 때만).
- **Ctrl+V 순서:** 창 어디에서든 클립보드를 이 순서로 본다.
  1. 그림 데이터가 있으면 그것을 넣는다.
  2. 아니면 jpg·png 파일 하나가 있으면 그 파일을 넣는다.
  3. 둘 다 아니면 평소처럼 글자를 붙여 넣는다.
  - **예외:** 글자 칸에 커서가 있고 클립보드에 일반 글자(text/plain)도 있으면 글자를 붙여 넣는다(엑셀·워드 복사는 그림과 글자를 함께 담는다). 2026-10-31 검토 반영.
  - 브라우저의 "이미지 복사"는 보통 그림만 담으므로 글자 칸에서도 그림이 들어간다. 실제 확인 때 본다.
- **끌어다 놓기 순서:**
  1. 놓은 것에 그림 데이터가 있으면 그것.
  2. 아니면 로컬 jpg·png 파일 하나(지금처럼).
  3. 아니면 `http`/`https` 주소 하나면 그 그림 하나만 받는다.
- **그림 데이터:** JPEG(품질 90)로 바꿔 넣는다. 그 뒤는 5-A 규칙(jpg·png, 10 MB까지)을 그대로 따른다.
- **주소 받기:**
  - 한 번에 하나, 시간 제한 10초, 10 MB 넘으면 그만 받는다.
  - User-Agent는 MusicBrainz와 같다.
  - 받는 동안 회색 `그림 받는 중…`. 실패하면 빨강 `그림을 받지 못했습니다`.
  - 받은 바이트가 jpg·png가 아니면 5-A 문구 `jpg·png 그림만 넣을 수 있습니다`.
  - 늦게 온 응답은 5-A 찾기처럼 요청 번호로 버린다(다른 곡을 열었거나 창을 닫았으면 버림).

## 4. 파일 이름 바꾸기

### 4.1 창

- **위치:** 경로 줄 아래. 체크 `저장할 때 파일 이름도 바꾸기` + 미리보기 글 한 줄. 고칠 수 있을 때만 보인다.
- **기억:** 체크 상태는 설정 `player_rename_on_save`(기본 꺼짐)에 남아 다음에 창을 열 때도 그대로다.
- **미리보기 글(체크가 켜졌을 때만):**
  - 새 이름이 지금과 다르면 갈색 `#8A6D00` `→ <b>{새 파일 이름}</b>`.
  - 같으면 회색 `(지금 이름과 같음)`.
  - 가수나 제목이 비면 회색 `가수와 제목이 있어야 파일 이름을 바꿀 수 있습니다.`
  - 가수·제목은 있는데 경로가 너무 길어 이름을 만들 수 없으면 회색 `이름이 너무 길어 바꿀 수 없습니다.`
  - 지금 이름과 새 이름은 한글 정규화(NFC) 뒤에 비교한다(맥에서 온 파일 이름이 같아 보이는데 바뀌지 않게).
  - 다른 파일이 이미 그 이름이면 빨강 `같은 이름의 파일이 이미 있습니다`. 이 상태에서 칸을 고쳐 `[저장]`을 누르면 §4.3-1대로 아무것도 저장하지 않는다(고친 칸은 그대로 남는다).
- **바꿀 이름이 있음:** 체크가 켜졌고, 새 이름이 지금과 다르고, 겹치는 파일이 없는 상태.
  - 이때는 칸을 고치지 않았어도 `[저장]`이 켜진다.
  - 다만 "저장 안 한 내용" 묻기에는 들어가지 않는다. 체크만 켜 둔 채 다른 곡을 열 때마다 묻지 않게 하기 위해서다.
  - 노란 안내 줄도 칸이나 그림이 바뀌었을 때만 나온다.

### 4.2 이름 규칙

- **이름:** `{가수} - {제목}{원래 확장자}`. 가수·제목은 저장할 칸 값(앞뒤 빈칸 정리)이다.
- **정리:**
  - 바꾸는 글자: `\ / : * ? " < > |`와 제어 문자(0x00–0x1F) → `_`.
  - 줄이는 것: 빈칸 여러 개 → 하나. 끝의 `.`과 빈칸 → 떼어 냄.
  - 정리 뒤 가수나 제목이 비면 바꾸지 않는다.
- **Windows 예약 이름:** 이름(확장자 앞)이 `CON PRN AUX NUL COM1–COM9 LPT1–LPT9`(대소문자 무시)이면 뒤에 `_`를 붙인다.
- **길이:**
  - 이름은 확장자 포함 150자까지이고, 넘으면 제목 끝을 자른다.
  - 전체 경로가 259자를 넘으면 그만큼 더 자른다.
  - 자른 끝에 남은 `.`과 빈칸은 다시 뗀다.
  - 그래도 제목이 한 글자도 안 남으면 바꾸지 않는다.
- **폴더·확장자:** 같은 폴더 안에서만 바꾸고, 확장자는 원래 글자 그대로다.

### 4.3 저장 순서 (안전)

1. **먼저 확인:** 새 경로에 다른 파일이 있으면 아무것도 쓰지 않는다. 빨강 `같은 이름의 파일이 이미 있습니다 ({새 이름}). 아무것도 저장하지 않았습니다.`
   - 대소문자만 다른 같은 파일(`a.mp3` → `A.mp3`)은 겹침이 아니다.
2. **내리기:** 지금 올라간 파일이면 내린다(5-A와 같음).
3. **태그 쓰기:** 칸·그림이 바뀌었을 때만 쓴다. 실패하면 5-A처럼 원본 그대로, 같은 자리로 다시 올리고, 이름도 바꾸지 않는다.
4. **이름 바꾸기:** `os.rename`을 쓴다(덮어쓰지 않음).
   - 실패하면 태그는 저장된 채 빨강 `태그는 저장했지만 파일 이름은 바꾸지 못했습니다 (다른 프로그램이 쓰는 중이거나 권한이 없습니다).`
   - 태그도 안 바뀐 경우(이름만 바꾸려던 경우)는 빨강 `파일 이름을 바꾸지 못했습니다 (다른 프로그램이 쓰는 중이거나 권한이 없습니다).`
5. **다시 올리기:** 새 경로(실패했으면 원래 경로)로 같은 자리·같은 상태에서 다시 올린다(5-A 규칙).
6. **함께 고치기:**
   - 재생목록의 같은 경로 곡들(대소문자 무시)을 모두 새 경로로 바꾼다. 줄 글자는 바로 바뀐다.
   - 설정 `player_last_track`이 옛 경로면 새 경로로 바꾼다.
   - 이어 듣기 세션 파일(last.m3u8)은 다음 저장 때 새 경로로 써진다.
7. **기록:** 앱 폴더의 `rename_log.txt`에 한 줄 더한다(§4.4).
8. **창 글:** 초록 `#1E7B34` `저장했습니다 · 파일 이름을 바꿨습니다` + 파란 링크 `되돌리기`. 이름만 바꿨으면 `파일 이름을 바꿨습니다` + `되돌리기`.

### 4.4 되돌리기와 기록

- **기록 파일** `%APPDATA%\my-fun\rename_log.txt`:
  - UTF-8, 한 줄에 `시각(ISO, 초까지)\t옛 경로\t새 경로`.
  - 최근 200줄만 남기고, 깨진 줄은 무시한다(깨진 바이트가 있어도 나머지 줄은 살린다).
- **창이 고치는 중일 때:** 메뉴로 되돌렸는데 곡 정보 창이 그 파일을 보여 주며 저장 안 한 칸이 있으면, 칸은 그대로 두고 경로만 옛 경로로 바꾼다.
- **되돌리기:** 마지막 줄을 되돌린다(새 경로 → 옛 경로). 이름만 되돌리고 태그는 그대로 둔다. 순서는 §4.3의 내리기·다시 올리기·함께 고치기와 같다.
  - 성공하면 그 줄을 지운다. 창 글은 `파일 이름을 되돌렸습니다`.
  - 새 경로 파일이 없으면 그 줄을 지우고 빨강 `되돌릴 파일이 없습니다 ({새 이름})`.
  - 옛 이름에 다른 파일이 생겼으면 그 줄을 남기고 빨강 `원래 이름의 파일이 이미 있습니다 ({옛 이름})`.
  - 그 밖의 실패는 그 줄을 남기고 빨강 `파일 이름을 되돌리지 못했습니다 (다른 프로그램이 쓰는 중이거나 권한이 없습니다).`
- **창의 `되돌리기`:** 그 창에서 방금 바꾼 것을 되돌린다. 마지막 기록 줄이 그 바꾼 것일 때만 보인다. 되돌린 뒤에는 창이 옛 경로의 정보로 다시 채워진다.
- **목록 우클릭 메뉴:** `곡 정보 고치기…` 아래에 `이름 되돌리기: {새 이름} → {옛 이름}`. 기록이 있을 때만 보인다. 각 이름은 40자가 넘으면 `…`로 줄인다. 성공·실패는 플레이어 상태 줄에 같은 문구로 알린다.

### 4.5 5-B와의 관계

즐겨찾기(5-B)는 파일 경로로 기억한다. 그래서 5-B는 이름 바꾸기·되돌리기 때 함께 고치기(§4.3-6)에 즐겨찾기 경로를 더해야 한다. 이번 단계에서는 컨트롤러에 그 자리(`_rename_everywhere`)만 만든다.

## 5. 문구·색

| 쓰임 | 문구 | 색 |
|---|---|---|
| 줄 이름 | `브라우저로 찾기` | 회색 |
| 단추 | `지니에서 찾기`, `멜론에서 찾기` | — |
| 안내 | `보고 직접 입력`, `끌어다 놓기 · Ctrl+V` | 회색(작게) |
| 체크 | `저장할 때 파일 이름도 바꾸기` | — |
| 미리보기 | `→ {이름}` | 갈색 `#8A6D00` |
| 미리보기 | `(지금 이름과 같음)`, `가수와 제목이 있어야 파일 이름을 바꿀 수 있습니다.` | 회색 |
| 미리보기 | `같은 이름의 파일이 이미 있습니다` | 빨강(5-A 오류색) |
| 저장 뒤 | `저장했습니다 · 파일 이름을 바꿨습니다`, `파일 이름을 바꿨습니다`, `파일 이름을 되돌렸습니다` | 초록 `#1E7B34` |
| 저장 뒤 링크 | `되돌리기` | — |
| 메뉴 | `이름 되돌리기: {새} → {옛}` | — |
| 그림 받기 | `그림 받는 중…` | 회색 |
| 그림 받기 실패 | `그림을 받지 못했습니다` | 빨강 |

오류 문구는 §4.3·§4.4 그대로 쓴다. 5-A의 `저장했습니다`(회색)는 이름을 바꾸지 않은 저장에 그대로 둔다.

## 6. 시험

- **이름 규칙 단위 시험:** 쓸 수 없는 글자, 예약 이름, 길이, 대소문자만 바뀜, 겹침.
- **컨트롤러:**
  - 듣는 중·일시정지 중 이름 바꾸기 → 새 경로로 같은 자리.
  - 겹침 → 아무것도 안 씀.
  - 이름 실패 → 태그만 저장.
  - 목록·last_track 갱신, 기록, 되돌리기.
- **창:** 미리보기 문구, 체크 기억 신호, `[저장]` 켜짐, Ctrl+V 그림/글자 구분, 끌어다 놓기 세 경우, 주소 받기 늦은 응답.
- **주소 만들기:** 한글·빈칸 인코딩, 빈 칸 → 파일 이름 짐작.
- 네트워크·실제 브라우저는 시험에서 쓰지 않는다(가짜 fetch·open_url).
- **실제 확인:** Test-mp3 사본으로 듣는 중 이름 바꾸기·되돌리기, 지니·멜론 주소가 브라우저에서 검색 결과로 열리는지.
