# 5-A단계 설계 — 곡 정보 고치기 · 자동 태그 (H-3, H-4)

> 시안 `docs/images/stage5a_mockup.png` 승인 2026-10-31("응 진행해"). 기반: 4-B 통과 `main` `bbad79e`.
> 5-B(즐겨찾기)는 이 단계가 끝난 뒤 따로 한다.

## 1. 목표

곡 정보 창에서 제목·가수·앨범·년도·장르·트랙과 앨범 그림을 고쳐 MP3 파일에 저장한다. 빠진 정보는
사용자가 누를 때만 MusicBrainz에서 찾아 채운다. 태그를 모두 지울 수도 있다.

## 2. 여는 곳

- 앨범 그림 클릭, `Ctrl+I`: 지금 곡(지금처럼).
- 재생목록 우클릭 메뉴: 글자를 `곡 정보…` → `곡 정보 고치기…`로 바꾼다. 커서 줄의 곡.
- 라디오 정보, MP3가 아닌 파일, 없는 파일: 창은 지금처럼 보기만 한다(칸은 읽기 전용, 그림 단추·찾기·지우기·저장 숨김).
  MP3가 아니면 회색 안내 `MP3만 고칠 수 있습니다`, 없는 파일이면 `파일이 없습니다`.
- 여러 곡을 골라도 커서 줄 한 곡만(일괄은 H-5, 나중).

## 3. 창

창 제목 `곡 정보`. 모양은 시안 그대로.

- 위: 왼쪽 그림 120px + `[그림 넣기…]` `[빼기]`. 오른쪽 칸: 제목 / 가수 / 앨범 / 년도 / 장르 / 트랙(입력),
  길이 / 형식 / 크기(글자). 년도·트랙 칸은 좁게(최대 70px).
- 장르 칸은 고쳐 쓸 수 있는 목록: `발라드, 댄스, 록, 팝, 힙합, 알앤비, 재즈, 클래식, 일렉트로닉, 트로트, 어쿠스틱, 블루스, 인디, OST`.
- 경로 줄(지금처럼).
- `인터넷에서 찾기 (MusicBrainz)` 접힘 줄(화살표 단추, 처음엔 접힘, 펼침 상태는 창이 기억 — 저장 안 함).
- 아래 단추: 왼쪽 `[태그 모두 지우기…]`, 오른쪽 `[폴더 열기]` `[저장]`(기본 단추) `[닫기]`.

### 바뀐 값 표시

- 처음 연 값과 다른 칸은 배경 `#FFF6D6`. 그림이 바뀌면 그림 테두리 2px `#E8B400`.
- 바뀐 것이 하나라도 있으면 `[저장]`이 켜지고, 없으면 꺼진다. 아래에 갈색(`#8A6D00`) 한 줄
  `노란 칸 = 바뀐 값 (아직 저장 안 됨)`.
- 저장 안 한 채 `[닫기]`/창 닫기/다른 곡 정보 열기 → 묻기 `저장 안 한 내용이 있습니다. 버릴까요?` (예=버림, 아니요=그대로 남음).
- 앞뒤 빈칸은 저장할 때 잘라 낸다.

### 그림

- `[그림 넣기…]`: 파일 고르기(`그림 (*.jpg *.jpeg *.png)`). 창에 jpg/png 파일을 끌어다 놓아도 같다.
- jpg(FF D8)·png(89 50 4E 47) 바이트만 받는다. 아니면 빨간 안내 `jpg·png 그림만 넣을 수 있습니다`. 10 MB 넘으면 `그림이 너무 큽니다 (10 MB까지)`.
- `[빼기]`: 곡에 든 그림을 지우기로 표시(저장 때 지움). 폴더의 cover.jpg 등은 건드리지 않는다. 그림이 없으면 꺼짐.
- 보이는 그림: 넣을 그림 > (빼기면 음표) > 지금 곡의 그림(폴더 그림 포함, 지금처럼).

### 태그 모두 지우기

- 누르면 단추 줄 위에 확인 줄 `태그와 그림을 모두 지웁니다. 소리는 그대로입니다. [지우기] [그만두기]`.
- `[지우기]`는 바로 파일에서 ID3 태그(v1·v2)를 지우고 창을 새로 읽은 값으로 채운다.

## 4. 인터넷에서 찾기 (MusicBrainz)

- 펼치면 `제목`/`가수` 칸과 `[찾기]`, 결과 목록(최대 10줄), `☑ 빈 칸만 채우기`(기본 켬), 상태 글, `[고른 곡으로 채우기]`.
- 처음 펼칠 때 칸을 미리 채운다: 태그 제목·가수가 있으면 그것, 없으면 파일 이름에서 짐작(§4.1).
- 네트워크는 `[찾기]`(또는 칸에서 Enter)와 `[고른 곡으로 채우기]`(그림 받기)를 누를 때만.
- 결과 줄: `제목 · 가수 · 앨범 · 년도`(빈 것은 뺌). 처음 줄을 고른 상태로.
- 상태 글(회색): `찾는 중…`, `{n}곡 찾음`, `찾은 곡이 없습니다`, `앨범 그림 받는 중…`, `앨범 그림 받음`, `앨범 그림 없음`.
  실패는 빨강 `인터넷에 연결하지 못했습니다` / `MusicBrainz가 바쁩니다. 잠시 뒤 다시 눌러 보세요`(503).
- `[고른 곡으로 채우기]`: 고른 결과의 제목·가수·앨범·년도·트랙·장르를 칸에 넣는다.
  빈 칸만 채우기가 켜져 있으면 비어 있는 칸만. 그림은 곡에 그림이 없을 때(또는 빈 칸만 채우기가 꺼졌을 때)만 받아서 넣는다.
  저장은 하지 않는다(노란 칸이 된다).
- 응답이 늦게 와서 창이 이미 다른 곡을 보고 있으면 버린다.

### 4.1 파일 이름에서 짐작

`core/tagguess.py` `guess_from_filename(path) -> tuple[str, str]` (가수, 제목). 확장자 뗀 이름에서:
1. 맨 앞 `[…]` 한 덩어리 → 가수 후보, `(…)` 덩어리는 버림. 예: `[서지원] I Miss You` → (서지원, I Miss You).
2. ` - `로 나눠 둘 이상이면 앞 = 가수, 둘째 = 제목. 예: `(홍대클럽)Benny Benassi - I Love My Sex(노래진짜좋음) - 클럽음악`
   → (Benny Benassi, I Love My Sex). 제목 끝의 `(…)` 덩어리는 버림.
3. 나머지는 이름 전체 = 제목, 가수 = 1번 후보 또는 "".
4. 결과 앞뒤 빈칸·`_` 정리.

### 4.2 MusicBrainz 규칙

- 주소 `https://musicbrainz.org/ws/2/recording?query=…&fmt=json&limit=10`. 질의 `recording:"제목" AND artist:"가수"`
  (가수 없으면 `recording:"제목"`). 따옴표·역슬래시는 이스케이프.
- User-Agent `my-fun/0.5 ( personal music player )`. 사용자 이메일 등 개인 정보는 보내지 않는다.
- MusicBrainz 호출 사이는 1초 이상(앱 전체 한 곳에서 지킨다). 시간 제한 10초.
- 결과 하나 = (녹음, 그 녹음이 실린 발매 하나). 녹음마다 발매를 앞에서부터 펼쳐 최대 10줄.
  년도 = 발매 날짜 앞 4자리, 트랙 = 그 발매에서의 트랙 번호, 장르 = 녹음 태그 중 count가 가장 큰 것(없으면 "").
- 그림: `https://coverartarchive.org/release/{release_id}/front-500`(리다이렉트 따라감). 404면 그림 없음.

## 5. 저장

### 5.1 파일에 쓰기 (`engine/tagwrite.py`, mutagen)

- `write_tags(path, fields, picture)`: `fields` = 제목·가수·앨범·년도·장르·트랙 글자, 빈 글자 = 그 태그 지움.
  `picture` = 새 그림 바이트 / `REMOVE` / `KEEP`.
- `clear_tags(path)`: ID3 v1·v2 모두 지움.
- 둘 다 안전 저장: 같은 폴더의 임시 사본(`.{이름}.myfun-tmp`)에 쓰고 → `read_info`로 다시 읽어 소리 길이가 있고
  제목(쓰기면)이 맞는지 확인 → `os.replace`로 원본과 바꿈. 어느 단계든 실패하면 사본을 지우고 원본은 그대로,
  `TagWriteError`(한국어 이유)를 낸다.
- 형식: 파일에 있는 ID3v2 버전을 그대로 둔다 — 이미 v2.4인 파일은 v2.4로(TSOP·TMOO 같은 프레임이 안 사라지고, 년도는 TDRC),
  v2.3·v2.2이거나 ID3v2가 없는 파일은 v2.3으로(년도는 TYER). 글자는 UTF-16(다른 프로그램에서도 한글이 안 깨지게),
  ID3v1은 지움(옛 CP949 값과 섞이지 않게).
  그림은 APIC 앞표지(type 3)로 쓰고 mime은 바이트로 정함. 그림을 바꾸거나 뺄 때는 앞표지(type 3과 type 0 "기타")만
  지우고, 뒷표지·가수 사진 같은 다른 그림은 그대로 둔다. 읽을 때(`read_info`)는 그림이 여럿이면 앞표지를 먼저 고른다.
  우리가 모르는 다른 태그 프레임(가사 등)은 그대로 둔다.
- 오류 문구: 권한/사용 중 → `파일에 쓸 수 없습니다 (읽기 전용이거나 다른 프로그램이 쓰는 중)`, MP3 아님 → `MP3만 고칠 수 있습니다`,
  확인 실패 → `저장한 파일을 다시 읽지 못해 원래대로 두었습니다`, 그 밖 → `저장하지 못했습니다`.

### 5.2 듣고 있는 곡이면

`PlayerController.save_tags(path, fields, picture)` / `clear_tags(path)`:
- 지금 플레이어에 올라간 파일이면: 위치·상태 기억 → `unload` → 쓰기 → 다시 `load` → 같은 위치로 → 재생 중이었으면 재생.
  쓰기가 실패해도 다시 올린다(원본 그대로이므로).
- 끝나면 곡 정보 캐시를 비우고, 효과 동기화 키를 지워 장르 자동 프리셋이 새 장르로 다시 골라지게 한다.
- 결과로 새 `TrackInfo`를 돌려준다. 실패는 `TagWriteError`를 그대로 올린다.

### 5.3 저장 뒤

- 창은 새로 읽은 값으로 다시 채워지고(노란색 없어짐) 아래 회색 `저장했습니다`.
- 패널: 부제목(가수 · 앨범), 앨범 그림, 효과 칸 `자동: …`이 다음 새로고침에 바뀐다.
- 실패: 창 아래 빨간 글로 이유, 칸 값은 그대로 남는다.

## 7. 테스트

- tagguess: §4.1 예 셋 + 빈 이름 + `가수 - 제목` 꼴.
- tagwrite(진짜 mp3 = `tone_mp3` 사본): 한글 제목 쓰고 PyAV로 다시 읽기; 빈 글자로 지우기; 그림 넣기·KEEP·REMOVE;
  ID3v1 지워짐; 모르는 프레임(USLT) 남음; MP3 아님 오류; 읽기 전용 파일 오류 + 원본 그대로 + 임시 파일 없음;
  확인 실패 흉내(verify가 False) → 원본 그대로; `clear_tags`.
- musicbrainz(가짜 fetch): 질의 문자열·이스케이프·UA; 응답 → 후보(년도·트랙·장르); 10줄 제한; 503/네트워크 오류;
  1초 간격(가짜 시계); 그림 404 → None.
- controller: 듣고 있는 곡 저장 → unload/load/seek/play 순서와 위치; 실패해도 다시 load; 장르 바뀌면 자동 프리셋 다시 보냄.
- 창: 바뀐 칸 노랑·저장 켜짐; 그대로 되돌리면 꺼짐; 그림 넣기(바이트 검사)·빼기; 닫을 때 묻기; 찾기 → 목록 → 채우기(빈 칸만 켜기/끄기);
  늦은 응답 버림; 지우기 확인 줄; 라디오·비MP3 읽기 전용.
- 패널: 메뉴 글자, 저장 뒤 부제목·그림 바뀜.

## 8. 완료 기준 (사용자 체크리스트)

- [ ] 앨범 그림 클릭, 우클릭 "곡 정보 고치기…", Ctrl+I로 곡 정보 창이 열린다
- [ ] 칸을 고치면 노랗게 되고 [저장]이 켜진다. 저장하면 큰 제목 아래 "가수 · 앨범"이 바로 바뀐다
- [ ] [그림 넣기…](또는 끌어다 놓기)로 앨범 그림을 넣고 저장하면 플레이어 그림이 바뀐다. [빼기]로 지울 수 있다
- [ ] 태그 없는 곡에서 [인터넷에서 찾기] → [찾기]로 곡 목록이 나오고, [고른 곡으로 채우기]로 빈 칸과 그림이 채워진다
- [ ] "빈 칸만 채우기"를 켜 두면 이미 있는 값은 바뀌지 않는다
- [ ] 듣는 중인 곡을 저장해도 잠깐 뒤 같은 자리에서 계속 나온다
- [ ] 저장한 한글 제목이 탐색기(속성 → 자세히)나 다른 플레이어에서도 깨지지 않는다
- [ ] [태그 모두 지우기…] → [지우기]로 태그가 지워지고 소리는 그대로 나온다
- [ ] 저장 안 하고 닫으면 버릴지 묻는다
- [ ] 라디오 정보는 고칠 수 없게 보기만 된다

## 9. 정한 것

- 쓰기는 mutagen(사용자 승인 2026-10-30), 읽기는 지금처럼 PyAV.
- MP3만 고친다. 여러 곡 한꺼번에 고치기는 H-5(나중).
- "빈 칸만 채우기" 기본 켬 — 빠진 것을 채우는 쪽이 이번 요청의 중심이라서.
- 결과는 자동으로 저장하지 않는다. 사용자가 보고 [저장]을 누른다.
- ID3 버전은 파일에 있는 것을 그대로 둔다 (v2.4는 v2.4, 그 밖은 v2.3). 처음 정했던 "항상 v2.3"은 TSOP·TMOO 등이 사라져서 바꿨다.
- 앱을 끝낼 때 곡 정보 창에 저장 안 한 내용이 있으면 `저장 안 한 내용이 있습니다. 버릴까요?`를 묻고, 아니오면 끝내지 않는다.
- 저장 전 원본 백업 파일은 남기지 않는다. 대신 사본에 쓰고 확인 뒤 바꿔치기(실패해도 원본 그대로).
