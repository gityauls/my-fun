# my-fun 개발 로드맵

> 작성 2026-10-24. 기능 근거는 `docs/alsong_features.md`(알송 3.56 매뉴얼 요약)이다. 진행 현황은 §9에 적는다.

## 1. 목표

- 음악 파일과 인터넷 라디오를 듣는 **작은 플레이어**를 만든다.
- 완성도가 충분해지면 데스크톱 캘린더(`C:\desktop_calendar_v2`, PyQt5)에 부속 부품으로 붙인다. 캘린더 설정의 "MP3·라디오" 체크박스를 켜면 나타나게 한다.
- 알송 매뉴얼은 기능을 고르는 메뉴판으로만 쓴다. 알송 전체를 따라 만들지 않는다.
- 빠른 MVP로 시작해서 기능을 하나씩 도장깨기로 늘린다.

## 2. 지킬 원칙

- 알송(이스트소프트)의 코드, 아이콘, 이미지, 문구, 이름을 쓰지 않는다. 기능 아이디어만 참고한다.
- REA 분석은 구현이 막혔을 때만 한다. 분석하더라도 동작 원리만 가져온다.
  - 설치 파일은 Inno Setup 6.4.2로 만들어져 있어서, 설치하지 않고 꺼내기 어려울 수 있다. 분석이 필요해지면 그때 설치할지 정한다.
- 광고, 통계, 외부 전송을 넣지 않는다. 라디오와 자동 태그는 사용자가 직접 누를 때만 인터넷에 접속한다.
- 화면은 PyQt5로만 만든다. 캘린더와 한 프로그램 안에서 돌아야 하기 때문이다. PySide6를 섞지 않는다.
- Python 3.13과 3.14 모두에서 돌아가야 한다. 회사 PC가 3.13이다.
- 소리를 다루는 부분(`core`, `engine`)은 화면과 분리한다. 화면 없이 테스트할 수 있어야 한다.
- 자동 테스트는 가짜 출력으로 숫자를 확인한다. 실제 소리는 사용자가 듣고 확인한다.
- 화면 문구는 한국어로 쓴다.
- 화면을 바꿀 때는 시안 이미지를 먼저 보여주고 승인을 받는다. 구현한 뒤에도 실제 화면을 보여준다.
- 캘린더 프로젝트(`C:\desktop_calendar_v2`)는 6단계 전까지 읽기만 한다.

## 4. 기술 구성

| 부분 | 선택 | 이유 |
|---|---|---|
| 화면 | PyQt5 5.15.11 | 캘린더와 같은 버전이다 |
| 디코딩 | PyAV (`av`, FFmpeg 포함) | 파일과 라디오 스트림(HLS 포함)을 모두 푼다 |
| 효과 | FFmpeg 필터(PyAV filter graph)를 먼저 쓰고, 모자라면 numpy로 만든다 | `equalizer`, `crossfeed`, `stereowiden` 같은 필터가 있다. 4단계에서 확인한다 |
| 출력 | sounddevice (PortAudio) | numpy 배열을 그대로 내보낸다 |
| 계산 | numpy | |
| 태그·앨범 이미지 | PyAV (이미 쓰는 것, 새 라이브러리 없음) | 2-B단계부터 |
| 자동 태그 | MusicBrainz 웹 API | 무료이고 키가 필요 없다. 초당 1회 제한이 있고 User-Agent를 보내야 한다. 5단계 |
| 테스트 | pytest, `QT_QPA_PLATFORM=offscreen` | |
| 개발 환경 | `my-fun\.venv` (Python 3.14) | |

## 5. 구조

```
my-fun/
├─ CLAUDE.md, requirements.txt, requirements-dev.txt, run.bat
├─ docs/            로드맵 · 단계 설계 · 구현 계획 · 매뉴얼 기능 목록
├─ funplayer/       캘린더에 넣을 패키지
│  ├─ core/         순수 로직 (화면·소리 없음): 곡 모으기, 재생목록 규칙, 설정
│  ├─ engine/       소리 (화면 없음): PyAV 디코딩 → 효과 → sounddevice 출력
│  ├─ controller.py 재생목록과 엔진을 잇는 규칙 (화면 없음)
│  ├─ ui/           PyQt5 화면: PlayerPanel(캘린더에 끼울 부품)
│  └─ __main__.py   혼자 실행할 때 쓰는 창
└─ tests/
```

- **캘린더 연결:** 캘린더는 `PlayerPanel(settings)` 하나만 만들면 된다.
  - 설정은 캘린더 config 안에 `player_`로 시작하는 키로 저장한다.
  - 혼자 실행할 때는 `%APPDATA%\my-fun\settings.json`에 저장한다.
- **소리 흐름:**
  - 디코딩 스레드가 2초 분량을 미리 채워 둔다. 라디오는 3단계에서 5~10초로 늘린다.
  - 출력 장치는 그 버퍼에서 꺼내 쓴다.
  - 화면은 초당 5번 재생 위치를 읽어 표시한다.
- **오류 처리:**
  - 못 여는 파일은 건너뛰고 다음 곡으로 간다.
  - 라디오가 끊기면 3번까지 다시 연결해 본다.
  - 출력 장치가 사라지면 정지하고 알린다.

## 7. 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| Python의 GIL 때문에 소리가 끊길 수 있다 | 출력 블록을 2048프레임(약 46ms)으로 잡고, 디코딩 스레드가 2초를 미리 채운다. 그래도 끊기면 블록과 버퍼를 키운다 |
| 재생이 PC 절전을 막는다 | 일시정지와 정지 때 출력 스트림을 멈춘다 |
| 라디오 주소가 바뀐다 | 방송국 목록을 파일로 따로 둔다. 방송사별 "주소 받아오기"를 바꿔 끼울 수 있게 만든다. 쓰면서 보완한다 |
| 캘린더 exe가 커진다 | PyAV, numpy, sounddevice로 약 60~80MB가 늘 것으로 본다. 6단계에서 실제로 잰다 |
| PyQt5와 PySide6가 충돌한다 | `funplayer`는 PyQt5만 쓴다 |
| 출력 장치가 바뀐다 (이어폰을 꽂는 경우 등) | 1단계에서는 정지하고 알린다. 자동 재연결은 써 보고 필요하면 넣는다 |
| MusicBrainz 이용 규칙 | 초당 1회를 지키고 User-Agent를 보낸다 |

## 8. 작업 방식 (매 단계 공통)

1. brainstorming으로 단계 설계를 정리한다 → `docs/stageN_design.md`
2. 화면이 바뀌면 시안 이미지를 보여주고 승인을 받는다.
3. writing-plans로 구현 계획을 쓴다 → `docs/superpowers/plans/`
4. 테스트를 먼저 쓰고 기능을 하나씩 만든다. 도장 하나를 커밋 하나로 남긴다.
5. 실제 화면과 소리는 사용자가 체크리스트로 확인한다.
6. §3 도장판과 §9 진행 현황을 고치고 로컬 git에 커밋한다. GitHub에는 올리지 않는다.
